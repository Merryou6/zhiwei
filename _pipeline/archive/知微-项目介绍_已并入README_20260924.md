## 一、为什么做「知微」

「知微」取自「见微知著」——从一道错题的细微之处，看见整个知识体系的破绽。

传统刷题产品的逻辑是**哪儿错补哪儿**：二次函数配错了，就再刷十道配方的题。但真实课堂里，一个学生配方出错的原因至少有四种：**符号意识没建立、运算基本功不牢、概念理解偏差、程序性步骤缺失**。补错了方向，刷再多题也只是把错误练得更熟练。

家长和老师面临的则是另一重困境：一张 78 分的试卷，只能告诉他们「孩子二次函数不行」，**说不出具体卡在哪一个知识节点、因哪一类错误**。诊断的粒度，决定了干预的精度。

知微要做的，就是把「感觉不行」变成「精确制导」：

> **每一分丢在哪里 → 归因到哪个知识点 → 属于哪类错误 → 开什么处方 → 用没见过的新题验证是否真的补上了。**

## 二、产品闭环：五步教学法的产品化

```
 ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐
 │ ① 采集   │   │ ② 诊断   │   │ ③ 归因   │   │ ④ 处方   │   │ ⑤ 验证   │
 │ 多源证据 │ → │ BKT建模  │ → │ 图谱定位 │ → │ 对话辅导 │ → │ 新题复测 │
 └─────────┘   └─────────┘   └─────────┘   └─────────┘   └─────────┘
  自报/测评      动态出题       根因分析       学长式引导     retest 池
  试卷/对话      掌握度状态带    错误分类       一步一引导     零重叠新题
                                                    ↓
                                        ΔAccuracy = 干预效果实测
```

| 步骤 | 学生看到的 | 系统里发生的 |
| --- | --- | --- |
| **① 采集证据** | 「我哪块儿没底」自报卡点、测评答题、拍照传试卷、和 AI 学长聊天 | 四路证据统一入库，多源证据融合 |
| **② 诊断掌握度** | 一道接一道的「恰到好处」的题 | BKT 引擎动态选题：太熟的不问、太生的先铺垫；每个知识点落到五档掌握度状态带 |
| **③ 定位根因** | 「你不是粗心，是符号意识这一环还晃」 | 沿知识图谱向上游回溯，区分「根因节点」与「表现节点」；错误落到类型学（概念 / 运算 / 程序 / 策略） |
| **④ 生成处方** | 一份看得懂的学习计划 + 一个不直接抛答案的 AI 学长 | 干预方案按状态带生成；对话遵循语气纪律——像耐心的学长，不像评判者 |
| **⑤ 新题验证** | 三道**从没见过**的复测题 | 复测题与训练题零重叠；ΔAccuracy 用实测回答「补上了没有」 |

**闭环的灵魂在第五步**：绝大多数产品在「辅导完成」就结束了，知微坚持用不重复的新题做干预后复测——效果不靠感觉，靠 ΔAccuracy。

## 三、五大核心亮点

### 1. 知识图谱归因，不是题库匹配

每个知识点节点都标注了**典型错误库**（初中 93 条 + 高中 56 条，共 149 条），每条错误都有可操作的描述。归因输出不是「你薄弱」，而是「你卡在 **B3 对称轴**，大概率属于**概念理解类·符号意识缺失**，上游 **A7 配方法** 也有松动」——然后沿图谱检查上游，避免「头痛医头」。

### 2. BKT 认知建模，掌握度是算出来的

采用经典的贝叶斯知识追踪（BKT）：每答一题，该知识点的掌握概率被证据实时更新，落到**五档掌握度状态带**（未触及 / 初识 / 摇晃 / 巩固 / 精熟），驱动选题、处方与图谱着色。引擎是**纯函数、零 IO** 的 TypeScript 实现，全部 17 个算法参数外置于 `config/params.json`——调参不动代码，教育学假设全部显式可审计。

### 3. 对话有教育学纪律，远程模型可插可退

AI 学长的每一轮引导遵循写进代码的纪律：

- **像耐心的学长，不像评判者**——「这一环还有点晃，我们再稳一下」，不说「你掌握很差」
- **一次只给一小步的方向性提示**，学生没明确要完整解法前不抛答案
- **状态机权威**：模型只产出结构化字段，学习路径决策权在确定性服务层，不被大模型自然语言覆盖
- **接得进真模型，也退得回本地**：默认零依赖的本地规则适配器，一行环境变量切换 DeepSeek 等 OpenAI 兼容大模型；远程任何失败自动回落本地，**永不白屏**
- SSE 流式输出逐字上屏，反代层直通不缓冲

### 4. C 端学习闭环 + B 端控制台，一个工程

- **C 端 10 个页面**：登录 → 学习空间 → 自报 → 测评 → 试卷 → 图谱 → 归因 → 报告 → 对话辅导 → 学习驱动
- **B 端控制台**：面向教师/研究者的深色驾驶舱，观察学生证据流与掌握度分布
- **多知识库架构**：初中数学（24 节点·二次函数主线）与高中数学（12 节点）双库并行，诊断 / 报告 / 对话 / 空间按知识库隔离，可继续扩展学段与学科
- **多学生空间**：一个账号可管理多个学习空间（家长二孩、教师多生场景）

### 5. 效果用硬指标说话

| 指标 | 设计 | 判据 |
| --- | --- | --- |
| **新题正确率提升** | 基线 3 题（retest 池）→ 干预 → 复测 3 题（**与基线零重叠**） | ΔAccuracy ≥ 0.3 且复测 ≥ 0.75 |
| **归因认可率** | 多名学生 ≥15 条归因记录，一线教师逐条判定 | ≥ 75%（冲刺 80%） |

演示数据全程可重置，所有数字以实测为准。

## 四、数据资产：AI 产品里最贵的部分

AI 应用的壁垒不在界面，在数据。知微的数据资产**全部结构化、可校验、可复用**：

| 资产 | 规模 | 说明 |
| --- | --- | --- |
| 知识图谱 | **36 节点**（初中 24 + 高中 12） | 含先修关系、章节归属、典型错误挂载 |
| 典型错误库 | **149 条** | 每条含错误描述与干预建议，归因与对话共用的「弹药库」 |
| 题目银行 | **404 题** | **train / retest 双池隔离**，复测题与训练题零重叠 |
| 算法参数 | 17 项外置 | BKT 初值 / 阈值 / 状态带边界，全部可调可审计 |

配套两道质检工序：静态校验脚本对数据结构、图谱连通性、双池重叠做**负例有牙**的断言；题库复算脚本对每题答案**逐一重算固化**，杜绝「错题库教错知识」。

## 五、技术架构

```
┌──────────────────────────────────────────────────────────┐
│  apps/web        React 18 + TS + Vite + Tailwind + Zustand │
│                  11 页面 · HashRouter · ECharts 图谱可视化  │
├──────────────────────────────────────────────────────────┤
│  functions/api    Node.js · 19 个 REST/SSE 接口            │
│                  Store 适配层（本地 JSON / CloudBase 可切换）│
│                  ModelAdapter 工厂（本地规则 / 远程大模型）   │
├──────────────────────────────────────────────────────────┤
│  packages/engine  BKT 引擎 · 纯函数 · 零 IO · 参数全外置      │
├──────────────────────────────────────────────────────────┤
│  data/            知识图谱 · 题库 · 知识库索引               │
│  config/          params.json（17 算法参数）                │
└──────────────────────────────────────────────────────────┘
```

**几条刻进工程的硬约束：**

- **答案不下发前端**——`answer` / `solution_steps` 字段在接口层被硬性过滤，杜绝「F12 看答案」
- **算法零硬编码**——所有阈值、初值、状态带边界只存在于 `config/params.json`
- **首屏轻量**——构建拆包后首屏仅 index ≈ 87 KB + react ≈ 165 KB；ECharts（约 1 MB）懒加载，只在图谱页拉取
- **同构部署**——本地开发、CloudBase 云函数、Docker 单容器三种形态同一套代码

## 六、工程质量：AI 时代的开发范式

这个项目本身就是 **AI 主导开发**的样本——全程由「总控 + 三子 Agent」流水线交付：

```
 planner（只读，出实现计划）→ implementer（照计划实现）→ reviewer（只读审查，出 VERDICT）
        ↑______________ FAIL 最多回炉 3 轮 ______________↑
```

- **契约先行**：`API_CONTRACT` > `ALGORITHM` > `DATA_SCHEMA` > `PRD` 四层文档**冻结版**驱动开发，优先级明确，冲突有法可依
- **测试全覆盖**：**23 个测试文件 · 269 个用例全部通过**，覆盖 BKT 引擎、19 个 API、前端组件与数据一致性
- **每日可演示**：里程碑制，每天交付一个可运行版本；三轮迭代（地基冲刺 → 后端 19 接口 → 前端闭环）全部经独立审查通过
- **git 留痕即评分材料**：每个模块完成立即提交，中文提交信息完整记录决策过程

## 七、三分钟跑起来

**本地开发**（Node 22+）：

```bash
npm install
npm run all          # 一条命令同时拉起后端 8787 + 前端 5173
# 浏览器打开 http://127.0.0.1:5173
```

**Docker 单容器部署**（任意 2 核 2G Linux 服务器）：

```bash
cp deploy/zhiwei.env.example deploy/zhiwei.env
# 填入 ZHIWEI_SERVER_SECRET（openssl rand -hex 32 生成，唯一必改项）
docker compose up -d --build
# 浏览器打开 http://<服务器IP>:8080 —— 完成
```

一个容器 = 静态前端 + API 同源流式反代，对外仅一个端口；用户数据由 volume 持久化，备份恢复各一条命令。想接真模型？在 env 里加四行配置切换 DeepSeek（详见 `deploy/DEPLOY.md`）。
